# Security Policy

## Reporting a vulnerability

Please report security issues privately rather than opening a public issue.
Use GitHub's [private vulnerability reporting][gh] on this repository, or email
the maintainer.

[gh]: https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing/privately-reporting-a-security-vulnerability

Include the version (`sys-sentient --version`), how to reproduce, and what an
attacker could achieve. Expect an acknowledgement within a few days.

## Supported versions

Pre-1.0. Only the latest tagged release receives fixes.

## Known limitations

These are current design limitations, not undisclosed vulnerabilities. They are
listed so operators can make an informed deployment decision.

### No TLS

The daemon serves plain HTTP. Run it behind a TLS-terminating reverse proxy
(nginx, Caddy, Traefik) for anything beyond localhost. Without that, session
cookies and the machine token travel in cleartext, and the session cookie
cannot carry the `Secure` flag (see Authentication below).

## Authentication

`/api/*` and `/ws/*` require a credential. There are two kinds.

**User sessions (browsers).** Accounts are stored locally with argon2id
password hashes (64 MiB, t=3, p=2) encoded as PHC strings, so the cost
parameters travel with each hash and can be raised without a migration. Signing
in issues a random 256-bit session token; only its SHA-256 is stored, so a
leaked database yields no usable sessions. The cookie is `HttpOnly`,
`SameSite=Strict`, `Path=/`, and carries `Secure` when the request arrived over
TLS or through a proxy setting `X-Forwarded-Proto: https`. It is deliberately
*not* set unconditionally: browsers discard `Secure` cookies on `http://`, so
doing that would silently lock out every plain-HTTP LAN deployment. Sessions
expire after 24 h idle and 30 days absolute; both are configurable under
`auth:`.

Roles are `admin` and `viewer`. Viewers are read-only; anything that changes
state or spends money — `POST /api/analyze`, alert acknowledgement, user
management — requires `admin`.

**Machine token (scripts).** `server.api_key` still works, sent as `X-API-Key`
or `Authorization: Bearer`. It is no longer embedded in the dashboard bundle,
and the `?api_key=` WebSocket query parameter has been removed.

**First run.** With no accounts, the daemon prints a single-use setup token to
its log and `/setup` exchanges it for the first admin. There is no default
password at any point.

**Login hardening.** Failed sign-ins return one generic message whether the
email exists or not, and an unknown email still pays for a dummy hash so
response timing does not enumerate accounts. Attempts are rate-limited per
client IP, which also bounds concurrent argon2 memory use.

**Disabling auth.** `server.insecure: true` turns all of this off for
throwaway local runs. The daemon logs a warning on every start; never use it on
a reachable network.

### Bind address

The server listens on all interfaces. Bind it to localhost or firewall the port
unless you intend it to be reachable.

### AI-suggested commands are not validated

`POST /api/analyze` returns shell commands generated by Google Gemini, each with
an `isSafe` flag **produced by the model itself**. The daemon does not validate,
sanitise or execute them, and the flag carries no guarantee. The dashboard only
copies commands to the clipboard — it never runs them. Read anything before you
paste it into a shell.

### What leaves the machine

With a Gemini API key configured, the daemon sends the current metric sample and
recent system logs to Google. IPv4 and IPv6 addresses, e-mail addresses and
home-directory usernames are redacted from logs, process names and the
top-process summary first (`internal/pii`). Everything else in the prompt —
CPU, memory, disk, network, load, temperature — is sent as-is.

Leave `gemini.api_key` empty to disable all outbound traffic. There is no
telemetry, analytics or phone-home of any kind.

### Rate limits

`POST /api/analyze` is limited to 5 requests then 1/minute per client address,
because each call costs money. `GET /api/logs` is limited because it shells out
to `journalctl`/`dmesg`. Limits are keyed on the socket address, not
`X-Forwarded-For` — behind a proxy every client shares one budget.
